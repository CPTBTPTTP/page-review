# page-review · 页面审查 Skill

对产品原型或页面（HTML / 小程序 / H5 / Web 后台等）进行**系统性审查**的 AI Skill，覆盖九个维度，输出结构化问题报告。

审查依据的是**外部客观标准**（行业认知 + 业界通用惯例），而非项目自定的 PRD。

## 九大审查维度

| 维度 | 说明 |
| --- | --- |
| 1. 信息完整性 | 页面该有的字段、数据、功能入口是否齐全 |
| 2. 逻辑正确性 | 流程、跳转、数据依赖、状态流转是否正确 |
| 3. 交互惯例与可用性 | 是否符合主流产品交互惯例、触控是否可用 |
| 4. 视觉规范与信息层级 | 布局、间距、截断、样式、信息层级是否规范 |
| 5. 文案规范 | 文案准确性、一致性、专业度 |
| 6. 全局一致性 | 跨页 / 跨模块的视觉与数据表现是否一致 |
| 7. 边界与容错 | 页面状态完备性与极端数据处理 |
| 8. 合规与安全 | 隐私、合规、安全（敏感场景启用） |
| 9. 功能合理性 | 功能是否必要、能否合并、口径是否自洽 |

## 目录结构

```
page-review/
├── SKILL.md                     # Skill 定义与执行流程
└── references/
    ├── 审查维度.md               # 九大维度完整定义与判断点
    ├── 通用惯例.md               # 不依赖项目文件的通用判断标准
    ├── 报告模板.md               # 报告结构骨架
    └── 行业惯例/                 # 各行业惯例清单（按需加载、可增删）
        ├── 电商.md
        ├── 宠物.md
        └── 医疗.md
```

## 安装

将本仓库下载后，把 `SKILL.md` 与 `references/` 一起放入你的 Skill 目录即可。

以 WorkBuddy 为例（用户级 Skill 目录）：

```
~/.workbuddy/skills/page-review/
├── SKILL.md
└── references/
    └── ...
```

其他支持 Skill 的 Agent 同理，放入对应的 skills 目录并命名为 `page-review`。

## 触发词

页面审查、审查页面、页面走查、UI 审查、原型审查、review 页面、评审页面。

## 使用方式

1. 告诉 Agent 要审查的页面（项目路径 / 页面文件），并尽量说明所属行业（如宠物、电商、医疗）。
2. Agent 会加载对应行业惯例与通用标准，逐页「读取源码 → 渲染截图对照 → 按维度输出」。
3. 最终生成一份结构化问题报告（含维度标签 + 问题描述 + 修改建议 + 定位到文件与行号）。

## 报告约定

- 只列确实存在的问题，正常项不展示。
- 不标注优先级（无 P0/P1/P2），由使用者自行判断是否修改。
- 每条问题尽量精确定位到文件 + 行号。
