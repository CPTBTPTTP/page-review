# 页面审查维度

审查按以下九个维度逐一检查。每个维度标注「依据来源」，体现总纲原则：行业认知为主，PRD 不用，仅配色/端尺寸等强相关项读项目文件。

## 核心维度（每次审查必审）

### 1. 信息完整性
- **定义**：页面该有的字段、数据、功能入口是否齐全。
- **依据来源**：行业认知（该类页面惯例上该有什么，不参照项目 PRD）。
- **判断点**：
  - 核心字段缺失（如订单详情缺金额明细、宠物档案缺身份码）
  - 必要入口缺失（如个人中心缺地址管理）
  - 关键信息未展示（价格、销量、评分等）
  - 该有的状态 / 操作缺失

### 2. 逻辑正确性
- **定义**：流程、跳转、数据依赖、状态流转是否正确。
- **依据来源**：通用标准（页面源码即可判断）。
- **判断点**：
  - 跳转目标错误
  - 流程中断（如验证码框无"获取验证码"按钮）
  - 依赖脆弱（sessionStorage / 缓存 / localStorage，刷新即失效）
  - 状态不可达、死胡同
  - 条件逻辑错误

### 3. 交互惯例与可用性
- **定义**：是否符合主流产品交互惯例，触控是否可用。
- **依据来源**：行业认知（主流产品惯例）+ 通用标准（触控热区）。
- **判断点**：
  - 主流交互惯例（快捷操作直接执行、危险操作二次确认、弹窗关闭方式）
  - 触控热区 ≥ 44px（移动端）
  - 手势冲突（下拉刷新 vs 滚动）、误触
  - 操作无反馈

### 4. 视觉规范与信息层级
- **定义**：布局、间距、截断、样式是否规范，关键信息是否突出。
- **依据来源**：通用标准（客观原则）+ 项目文件（仅配色 / 端尺寸）。
- **判断点**：
  - 对齐与栅格（错位、毛边）
  - 间距一致性
  - 留白与呼吸感（过挤 / 过空）
  - 视觉重心与主次（关键信息 / 主 CTA 是否突出，符合 F/Z 型浏览路径）
  - 层级清晰度（标题 / 正文 / 辅助通过字号、字重、颜色、间距拉开层级）
  - 对称与平衡（头重脚轻、左右失衡）
  - 元素分组（格式塔：接近性 / 相似性）
  - 比例与尺寸统一（图片比例、按钮尺寸、圆角规格）
  - 截断与溢出
  - 端形态贴合（读项目文件取端尺寸 / 安全区；缺失时降级为"是否贴合目标端画布"）

### 5. 文案规范
- **定义**：文案的准确性、一致性、专业度。
- **依据来源**：通用标准（语言规范）+ 行业认知（术语）。
- **判断点**：
  - 中英混杂（如"thumb_up 有用"）
  - 全角 / 半角标点
  - 术语统一（跨页一致，或符合行业通用叫法）
  - 单位准确
  - 语气一致、有无歧义 / 误导

### 6. 全局一致性
- **定义**：跨页 / 跨模块的视觉与数据表现是否一致。
- **依据来源**：通用标准（页面间互相参照，天然自足）。
- **判断点**：
  - 状态标签颜色跨页一致
  - 同义按钮文案一致
  - 同一数据值在不同页一致（价格 / 数量 / 状态）
  - 组件表现一致

### 7. 边界与容错
- **定义**：页面状态完备性与极端数据处理。
- **依据来源**：通用标准。
- **判断点**：
  - 四态完备：空态 / 加载态 / 异常态 / 无权限态
  - 超长文本溢出
  - 0 / 负 / 超大值
  - 特殊字符 / emoji
  - 图片加载失败、弱网 / 断网

## 扩展维度（按场景启用）

### 8. 合规与安全（涉及隐私 / 医疗 / 金融 / 政务等敏感场景时启用）
- **定义**：隐私、合规、安全。
- **依据来源**：通用标准 + 行业合规要求。
- **判断点**：
  - 个人信息脱敏（手机号 / 姓名 / 身份证）
  - 敏感数据授权展示
  - 内容合规、权限控制
  - 操作安全防错（二次确认、防重复提交）

### 9. 功能合理性（需要评估功能取舍 / 合并时启用）
- **定义**：功能是否必要、能否合并、口径是否自洽。
- **依据来源**：行业认知（同类产品惯例）。
- **判断点**：
  - 功能是否必要
  - 能否合并
  - 入口口径自洽
  - 与主流产品功能对标
