# 通用惯例（不依赖项目文件的判断标准）

以下标准在任何项目中都适用，不依赖项目设计文件。审查时直接参照。

## 一、数据格式

- **日期**：`YYYY-MM-DD` 或 `MM月DD日`；避免点号分隔（`2022.02.18`）。
- **日期时间**：`YYYY-MM-DD HH:mm`；详情页可精确到秒。
- **相对时间**：刚刚 / X 分钟前 / X 小时前 / X 天前（消息、通知类），超过 24 小时显示绝对时间。
- **金额**：保留 2 位小数，千分位分隔（`1,234.56`），货币符号统一；避免符号后多余空格（`¥ 2,196.00`）。
- **手机号脱敏**：`138****1234`。
- **姓名脱敏**：`张*`、`李**`。
- **身份证脱敏**：前 6 后 4，中间打码。

## 二、交互惯例

- **危险操作二次确认**：删除、注销、退款等不可逆操作需二次确认弹窗，确认按钮红色高亮。
- **快捷操作直接执行**：快捷问题、快捷短语点击后直接发送/执行，而非仅填充输入框。
- **表单防重复提交**：提交后按钮 loading 并禁用。
- **必填标记**：必填字段标红色星号 `*`。
- **错误提示**：红色文字显示在字段下方；提交失败显示具体原因。
- **空状态**：展示插画 + 文案 + 引导操作按钮（如"去添加"）。
- **异常状态**：展示错误提示 + "重新加载"按钮。
- **触控热区**：移动端可点击目标 ≥ 44×44px。

## 三、页面状态（四态必备）

每个数据页面都应覆盖：
1. 正常态：数据正常展示；
2. 空态 / 首次进入态：无数据时展示引导文案与新增入口；
3. 加载态：骨架屏或 loading；
4. 异常态：接口失败 / 网络异常，展示重试入口。

（无权限场景另需无权限态。）

## 四、视觉客观原则

- 元素沿统一栅格 / 基线对齐，无错位毛边。
- 同类元素间距一致，符合 4px 基础单位。
- 留白合理，信息密度适中，一眼能定位重点。
- 关键信息 / 主 CTA 处于视觉焦点。
- 标题 / 正文 / 辅助层级通过字号、字重、颜色、间距清晰区分。
- 相关元素就近分组，不相关元素分隔（格式塔原则）。
- 图片比例、按钮尺寸、圆角规格跨页统一。

## 五、文案客观原则

- 无中英混杂（按钮、标签、状态文案）。
- 标点全角 / 半角统一（中文语境用全角）。
- 同一概念跨页用同一叫法。
- 单位、数量、时间表述准确、无歧义。

## 六、边界与极端数据

- 超长文本：单行省略号，多行折叠可展开。
- 0 / 负 / 超大数值有合理展示，不破坏布局。
- emoji、特殊字符不导致溢出或乱码。
- 图片加载失败显示占位图，不破坏布局。

## 七、合规与安全（通用部分）

- 个人信息列表默认脱敏，详情需授权。
- 危险操作二次确认、防重复提交。
- 无权限时按钮隐藏或置灰并说明原因。
