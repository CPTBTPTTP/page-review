# 页面审查报告模板

每次审查生成独立文件，文件名统一为 `YYYY-MM-DD-页面范围.md`（例如 `2026-09-01-服务门店-门店详情-服务预约.md`），不追加到旧报告。

**本模板结构为固定标准，所有审查报告一律沿用，不再改动布局。**

---

> 审查日期：YYYY-MM-DD
> 审查方式：源码读取 + 渲染截图对照（[视情况补充环境说明，如"已注入本地字体，图标渲染正常"]）
> 审查范围：[列出被审查页面，如"07-服务门店、09-门店详情、10-服务预约"]
> 适用说明：
> - [项目特定约定，逐条列出：静态原型模拟数据/toast 属正常、状态栏与返回逻辑由全局脚本维护、图片类内容不审显示合理性等]
> - **审查规范（用户确认）**：① 图片/头像等用户上传类内容不审查显示是否合理；② 无需修改的内容不在审查文档中展示；③ 报告不标注优先级，由用户自行判断是否修改

## 报告规则

- 只列问题条目；"正常 / 无需修改 / 已复核通过"的条目一律不展示。
- 复核确认是误判的条目直接删除，不保留"已复核"标注。
- 不标注优先级（不写 P0/P1/P2），不设优先级汇总表，不写迭代顺序建议。
- 每条问题固定包含三个字段：**描述**、**修改建议**、**影响文件**（含行号，尽量精确定位）。
- 维度标签统一使用九维度：**信息完整性 / 逻辑正确性 / 交互惯例与可用性 / 视觉规范与信息层级 / 文案规范 / 全局一致性 / 边界与容错 / 合规与安全 / 功能合理性**。
