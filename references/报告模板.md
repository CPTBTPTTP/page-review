# 页面审查报告模板

按以下结构输出报告。每次审查生成独立文件，文件名建议 `页面审查-YYYY-MM-DD.md`（或 `review/YYYY-MM-DD-审查.md`）。

---

# [项目 / 页面范围] 页面审查报告

> 审查日期：YYYY-MM-DD
> 审查方式：源码读取 + 渲染截图对照
> 审查范围：[列出被审查的页面清单或范围]
> 审查依据：[本次采用的行业惯例 + 通用标准；若项目设计文件缺失，注明"按源码反推 / 通用默认值审查"]

---

## 一、全局问题（影响全部或多数页面）

- 【维度标签】问题描述
  - 位置 / 影响页面
  - 修改建议

## 二、逐页问题（按页面或文件名排序）

### XX-页面名.html
- 【维度标签】问题描述
  - 位置：第 N 行 / 某区块
  - 修改建议

---

## 报告规则

- 只列问题条目；"正常 / 无需修改 / 已复核通过"的条目一律不展示。
- 复核确认是误判的条目直接删除，不保留"已复核"标注。
- 不标注优先级（不写 P0/P1/P2），不设优先级汇总表，不写迭代顺序建议。
- 每条问题尽量精确定位到文件 + 行号，便于修改。
- 维度标签统一使用：信息完整性 / 逻辑正确性 / 交互惯例与可用性 / 视觉规范 / 文案规范 / 全局一致性 / 边界与容错 / 合规与安全 / 功能合理性。
